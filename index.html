센서마다, 항목마다 단계별 범위를 화면에서 설정합니다. 현장과 설비에 따라 기준을 다르게 둘 수 있습니다.

관리자, 담당자, 사용자 세 단계입니다. 사용자는 자신에게 배정된 건물의 센서만 볼 수 있습니다.

DuckDB

왜 DuckDB 인가

센서 데이터는 고쳐 쓰지 않고 쌓이기만 하는 시계열입니다. 기간이 길어질수록 일반 데이터베이스에서는 집계가 무거워집니다. 분석용 컬럼 엔진인 DuckDB 는 필요한 열과 기간만 읽어, 조회 시간이 쌓인 전체 양이 아니라 보려는 구간의 크기로 정해집니다.

REAL-TIME

실시간 집계와 분석을 한곳에서

새로 들어온 값을 분석 저장소에 바로 쌓아, 대시보드의 집계와 AI 분석이 같은 데이터를 읽습니다. 사용자·건물·권한 같은 관리 데이터는 여럿이 동시에 고치는 데이터라 관계형 데이터베이스에 둡니다.

04AI 분석

기준값에 닿기 전에,
평소와 다른 움직임을 찾습니다

기준값 경보는 값이 선을 넘어야 울립니다. 새로 쌓이는 센서 데이터로 평소 패턴을 학습해, 선을 넘기 전의 변화를 먼저 보여줍니다.

AI

새로 쌓이는 데이터로
센서마다 평소 모양을 학습합니다

MintSoft 의 계측 AI 모니터링과 같은 분석 엔진을 씁니다. 학습과 판정은 서버의 CPU 에서 돌고 GPU 가 필요 없으며, 센서 데이터를 외부 AI 서비스로 보내지 않습니다.

  1. 실시간 적재 — 센서 값이 들어오는 대로 분석 저장소에 쌓습니다.
  2. 패턴 학습 — 센서마다, 항목마다 시간대별 평소 모양을 학습합니다.
  3. 이상 징후 판정 — 기준값 안이라도 평소와 다른 구간을 표시합니다.
  4. 알림과 기록 — 기준값 경보와 함께 대시보드와 이력에 남깁니다.

07자주 묻는 질문

도입 전에 많이 묻는 것

화재·전기 안전 모니터링 솔루션은 무엇인가요?

건물에 설치한 화재 감지 센서와 전기 안전 센서의 값을 실시간으로 모아 대시보드에 보여주고, 정해 둔 기준을 넘으면 문자와 앱 푸시로 알리는 관제 시스템입니다. MintSoft 가 센서 연동, 관제 웹, 모바일 앱까지 개발합니다.

어떤 값을 측정하나요?

화재 감지 쪽은 일산화탄소(CO), 휘발성유기화합물(VOC), 가스, 열, 습도, 연기 여섯 가지입니다. 전기 안전 쪽은 부하 전압, 부하 전류, 누설 전류, 온도, 주파수 다섯 가지입니다. 센서가 보내는 항목이 다르면 수집 항목을 맞춰 개발합니다.

경보는 어떻게 판정하나요?

센서마다, 측정 항목마다 3단계 기준 범위를 설정해 두고 값이 어느 단계에 들어가는지로 판정합니다. 기준을 넘으면 발생 시각을 기록하고 건물 담당자에게 문자와 앱 푸시를 보내며, 값이 정상으로 돌아오면 복구 시각을 남깁니다.

실시간으로 수집하나요?

네. 센서가 MQTT 로 보내는 값을 수집기가 받아 형식과 범위를 검사한 뒤 바로 저장하고 대시보드에 표시합니다. 센서와 서버 사이는 TLS 로 암호화하고 인증 토큰으로 보호합니다.

AI 분석도 되나요?

됩니다. 3단계 기준값 경보에 더해, 새로 쌓이는 센서 데이터에서 평소 패턴을 학습해 기준값에 닿기 전의 이상 징후를 찾고, 앞으로의 값을 예측하고, 센서 상태를 점수로 보여줍니다. 오토인코더, Isolation Forest, 예측 모델 자동 선택을 쓰며 MintSoft 의 계측 AI 모니터링과 같은 분석 엔진입니다. 학습과 판정은 서버의 CPU 에서 돌고 GPU 는 필요 없습니다.

왜 DuckDB 를 쓰나요?

센서 데이터는 고쳐 쓰지 않고 계속 쌓이는 시계열이라, 기간이 길어질수록 일반 데이터베이스에서는 집계가 무거워집니다. 분석용 컬럼 엔진인 DuckDB 는 필요한 열과 기간만 읽으므로 조회 시간이 쌓인 전체 양이 아니라 보려는 구간의 크기로 정해집니다. 측정 데이터는 DuckDB 와 Parquet 에, 사용자·건물·권한 같은 관리 데이터는 관계형 데이터베이스에 둡니다.

서버 한 대로 센서를 몇 대까지 감당하나요?

12코어 CPU 와 1TB 디스크를 가진 서버 한 대를 기준으로, 10초마다 값을 보내는 센서 1,000대의 10년치(약 315억 행, 약 400GB)를 담습니다. 센서 1대가 1년에 쓰는 용량은 10초 간격에서 약 0.04GB 이고, 1TB 에 약 2만 센서·년이 들어갑니다. 같은 DuckDB·Parquet 엔진을 쓰는 계측 AI 모니터링에서 잰 값으로 계산한 것이며, 센서의 전송 간격과 항목 수에 따라 달라집니다.

공공기관 보안 요구사항을 맞출 수 있나요?

공공기관 보안성 검토 항목에 맞춰 개발한 경험이 있습니다. 접속 기록 1년 보관과 수정·삭제 차단, 비밀번호 복잡도·주기적 변경·재사용 금지, 관리자 기능의 접속 IP 제한, 전화번호 같은 개인정보 암호화, 센서 통신 인증을 코드에 넣습니다. 망 분리나 VPN 같은 인프라 항목은 발주 기관의 환경에 맞춰 협의합니다.

이미 설치된 센서나 다른 제조사 장비도 연동할 수 있나요?

센서나 게이트웨이가 MQTT 또는 HTTP 로 값을 내보낼 수 있으면 전송 형식을 맞춰 연동합니다. 처음 연동하는 장비는 전송 항목과 형식을 먼저 확인해야 합니다.
